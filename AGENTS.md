Read the exact versioned docs at https://docs.expo.dev/versions/v56.0.0/ before writing any code.

## Project Status Authority

Before performing any planning, implementation, audits, or architectural work, read `Forge-Legacy-Master-Status.md`.

Treat this document as the project's single source of truth for:

* Current project status
* Completion percentages
* Architecture Freeze status
* Current Sprint
* Decision Queue
* Recently Completed
* Next Milestones

Update `Forge-Legacy-Master-Status.md` whenever major work is completed or project status changes.

If information from conversation history conflicts with the dashboard, identify the discrepancy rather than assuming either source is correct.

### Status Commands

When the user issues one of these commands, respond as defined:

**Quick Status** — Return the Project Dashboard summary only (30-second overview).

**Full Status** — Read `Forge-Legacy-Master-Status.md` and provide a complete project status including: Dashboard, Current Sprint, Architecture Freeze, Documentation, Content, Implementation, Decision Queue, Risks, Next Milestones.

**Project Audit** — Perform a fresh repository-wide audit. Compare the dashboard against the repository, documentation, amendments, git history, and project structure. Update the dashboard if discrepancies are found, then report: Completed work, Missing work, Duplicates, Documentation gaps, Repository cleanup, Recommended next priorities.
