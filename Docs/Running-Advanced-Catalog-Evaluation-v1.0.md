## Section 1 — The Question and the Locked Context

The Running family (Stage 0A complete) is two programs at the family **minimum** (`Program-Ecosystem-Architecture-v1.0.md` §2.1, "minimum of 2"):

| Sort | Program | Level | Wk/Day/Total | Goal Alignment | Successor |
|---|---|---|---|---|---|
| 10 | Running Base I | BEGINNER | 8/4/32 | IMPROVE_RUNNING, IMPROVE_ENDURANCE | Running Base II |
| 11 | Running Base II | INTERMEDIATE | 10/5/50 | IMPROVE_RUNNING, IMPROVE_ENDURANCE | — terminal |

`Running-Family-Research-v1.0.md` Finding B established that Base II is **terminal by roadmap artifact, not journey-completeness** — there is no advanced, threshold-focused, tempo-focused, or race-preparation program in the launch catalog. "Running Advanced" exists only as a Year-1 roadmap candidate (`Program-Ecosystem-Architecture-v1.0.md` §7.1: ADVANCED, OUTDOOR, "athletes graduating Running Base II ready for structured threshold, tempo, and race-pace training").

The question is **not** whether Running Advanced can be designed (it can). It is whether it **belongs in the launch catalog**.

## Section 2 — Repository Evidence

Six facts, each verified directly against current repository text, bear on the decision:

1. **The roadmap's own promotion gate (PEA §7.1).** Year-1 candidates are "Not committed. Each requires athlete demand signal validation before entering the catalog pipeline. Each must pass the standard expansion gate." Promotion is **demand-gated by the catalog's own governance** — and a demand signal is, by definition, unobtainable before launch.

2. **INTERMEDIATE-terminal is the majority launch posture (PEA §5).** Of the launch ladders, **six stop at INTERMEDIATE** — Conditioning, Body Recomposition, Hybrid, Lower Body, Mobility, and Running — while only **three reach ADVANCED** (Strength, Muscle Building general, Bodyweight). A family ending at INTERMEDIATE is the norm, not an anomaly that demands correction.

3. **Direct precedent — the Lower Body ladder (PEA §5, §7.1).** Lower Body Foundation → Lower Body Intermediate is INTERMEDIATE-terminal, with **"Lower Body Advanced" sitting in the very same §7.1 roadmap table** as Running Advanced. This identical posture was accepted when the Muscle Building family was taken through Stage 1 and judged Stage-1-complete (`Muscle-Building-Family-Stage-1-Review-v1.0.md`). Promoting Running Advanced while Lower Body Advanced stays roadmap-only would be internally inconsistent.

4. **Promotion pulls a cluster, not a single program (PEA §7.1).** The roadmap lists **both** "Running Advanced" and "5K Starter" (a race-goal beginner program). Opening the catalog to advanced/race-oriented running content invites the whole cluster, not one rung.

5. **Race content pressures a deferred goal alignment (PEA §5.1).** The launch catalog covers 8 of 10 goal alignments; **SPORT_PERFORMANCE is deliberately deferred.** Race-pace / race-preparation content is exactly the territory that would pressure SPORT_PERFORMANCE into scope.

6. **Curated-catalog philosophy (PCA PC-D4).** "The launch catalog is intentionally curated. The product is not a content platform… Quality over quantity." Restraint is the explicit design stance; the bar for adding a launch program is high.

## Section 3 — Answers to the Evaluation Questions

### A — What athlete problem would Running Advanced solve that Running Base II does not?

A **genuine** one. Base I and Base II are aerobic-**base** programs — easy-volume-dominant, with the family identity being injury-aware accumulation of aerobic base (`Running-Family-Research-v1.0.md` Deliverables 1, 4). Neither delivers structured high-intensity development. Running Advanced would serve the experienced runner who has exhausted what base-building offers and needs threshold, tempo, and race-pace work. This is a real, non-redundant problem.

**But a real problem is not automatically a launch-gated one.** The existence of the gap is established (Finding B); the question is timing and catalog fit, addressed below.

### B — Is the current Running ladder meaningfully incomplete without it?

Incomplete, yes — but **not meaningfully incomplete *for launch*.** The running journey ending at INTERMEDIATE is identical in kind to five other launch ladders (§2, evidence 2) that ship as-is. The incompleteness is real at the level of long-term product ambition, and entirely ordinary at the level of a curated launch catalog. Running is not an outlier requiring exceptional treatment.

### C — Would Running Advanced strengthen or weaken catalog coherence?

**At launch, it weakens coherence on balance.** It would be the catalog's first race-oriented program, pressuring race-distance specialization and the deliberately-deferred SPORT_PERFORMANCE alignment (§2, evidence 4–5) — i.e., scope creep into territory the catalog explicitly held back. The demand-signal gate (evidence 1) exists precisely to keep speculative rungs out until validated.

The timing matters, not the merit: **post-demand-signal, Running Advanced would *strengthen* coherence** by closing the journey gap. The coherence problem is "now," not "ever."

### D — Should the launch catalog remain Base I → Base II, or become Base I → Base II → Advanced?

**Remain `Running Base I → Running Base II`** for launch.

### E — Would promoting Running Advanced create downstream requirements?

Yes — material ones:
- **Race-specific programs.** "5K Starter" is the literal next Running roadmap item (§2, evidence 4); promoting advanced/race content invites it.
- **Endurance specialization pressure.** Threshold/tempo/race-pace opens distance- and goal-specialized branches the family has so far avoided.
- **SPORT_PERFORMANCE activation.** Currently deferred (§2, evidence 5); race-prep pulls it toward scope.
- **Process precedent.** Promoting it outside the demand-signal/expansion gate would set a precedent that bypasses the governance every other roadmap candidate is subject to (including Lower Body Advanced).

### F — Is the family minimum (2 programs) sufficient for launch despite the journey gap?

**Yes.** `Program-Ecosystem-Architecture-v1.0.md` §2.1 sets the floor at 2; the Mobility family launches at exactly 2, and six ladders stop at INTERMEDIATE (§2, evidence 2). The gap is a roadmap item, appropriately deferred — it is not a launch blocker, and the Stage 0A governance PASS (per-program justification) stands independently of it.

## Section 4 — Recommendation

**Running Advanced remains roadmap-only for launch.**

The athlete problem is real (A), but every catalog-fit signal points to deferral: the family is not anomalously incomplete (B), promotion weakens coherence at launch (C), it triggers real downstream obligations (E), the 2-program floor is satisfied (F), and — decisively — the catalog's **own roadmap governance requires a demand signal and expansion-gate pass that cannot exist before launch** (§2, evidence 1). The Lower Body precedent (§2, evidence 3) confirms this is the consistent treatment, not special restraint applied to Running.

**This verdict is time-bound, not permanent.** It is "remain roadmap-only **for launch**," and the single condition that would reopen it is the §7.1 gate: a post-launch athlete demand signal.

**Forward priority — Running Advanced is the first-priority Running expansion candidate.** When post-launch demand justifies reopening the Running family, Running Advanced should be evaluated **first**, ahead of the family's other roadmap candidate (5K Starter). Repository basis:
- **Running Advanced is the natural successor to the existing Base II** — it adds one rung to a live ladder, directly closes Finding B, and serves runners already in the funnel.
- **5K Starter is a net-new beginner race-entry branch** — a different entry point that adds breadth rather than completing the existing journey, and carries the heavier downstream weight (race-distance specialization, SPORT_PERFORMANCE).

So the post-launch sequence is: **Running Advanced first; then evaluate 5K Starter separately.** This is a prioritization, not a commitment to build either — both remain subject to the §7.1 demand-signal/expansion gate.

- **Architecture:** LOCKED and unchanged by this evaluation (PEA v1.4, PAS v1.3, PCA v1.4). - **Content Production:** The Running family's Stage 0A is complete; this evaluation triggers **no** Stage 1 Blueprint (deferring Running Advanced means there is nothing new to blueprint). Base I and Base II remain the only Running Stage 1 candidates.
