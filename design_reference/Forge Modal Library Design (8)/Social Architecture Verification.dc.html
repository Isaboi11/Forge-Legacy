Architecture & product-boundary verification

Posting & comments across the three social surfaces

Verifying how the completed Community Post Detail and Community Composer should extend to Communities, Squads, and the Friends Feed — what to share, what to keep distinct, and what to change. Not a request to make the three feeds identical.

Verdict — the boundary is sound; the shell was the gap

No universal "post" schema exists — each surface already has its own domain model, so the coupling the brief warns against has not happened. The real gaps: Post Detail was origin-blind (hard-wired to the community store, title fixed to "Post"), and Squads have no threaded post model at all. This pass adds the two missing models and an origin-aware Post Detail shell without merging semantics.

01 — Current behavior
Communities
Complete

The broadest surface. ForgeCommunityPosts keyed by communityId, seed + localStorage overlay.

  • 10-type role-gated taxonomy (discussion → paid program)
  • Two-step, role-aware composer (member / mod / owner)
  • Post Detail: thread, one-level replies, Top/Newest, respect, save · share · report → moderators
Squads
No post model

Squad Detail renders an ambient activity feed — not a post store.

  • Feed = weekly summary, PR, honor, competition, goal, workout
  • React / comment buttons only fire toasts — no threads
  • No composer, no Post Detail, no deep-link
  • Domain today: check-ins, missions, goals, competitions, honors
Friends Feed
Complete · self-contained

The simplest, most personal surface. Its own model, held inline in the view (not a store file).

  • Kinds: note / photo / video / progress / milestone
  • Own multi-reaction vocab & lightweight composer sheet
  • Audience: friends / squad / both — never public
  • Own in-component detail + ?post= deep-link
02 — Gaps & accidental coupling
No undifferentiated schema — good.Each surface owns its model. ForgeCommunityPosts is genuinely community-only. Nothing treats all social posts as one type. The universal-store risk the brief calls out does not exist.
Gap — Post Detail was origin-blind.The shell read only forge.community / forge.post, knew only the community store, and fixed its title to "Post". It could not render a squad or friend post or preserve where the reader came from. Fixed this pass → Adaptive Post Detail.
Gap — Squads have no threaded post model.Squad Feed items are ambient and dead-end (toasts). If squad content needs threads, a squad-scoped store is required — and it must enforce the training-only contract, not borrow the community taxonomy. Proposed this pass → ForgeSquadPosts.
Minor — Friends model lives inside the view.The Friends feed keeps its posts in component state (RAW + myPosts), so notifications, deep-links, and a shared Post Detail can't reach them cleanly. Extract to ForgeFriendsPosts — reuse without merging semantics.
Gap — report routing was community-only."Report submitted to moderators" is wrong for Friends (no moderators) and Squads (a captain, not community mods). Report target must follow origin. Fixed this pass in the adaptive overflow.
