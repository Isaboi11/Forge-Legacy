### 0. Two PO reports on Competitions — an invited friend was never told, and the standings screen has been dead since 0099 (2026-08-17, C-1/C-3 — **MIGRATION `0163` REQUIRED**, code is OTA-safe)

**(1) `column reference "tz" is ambiguous` (42702) — C-3 has never loaded for anyone.** `challenge_detail()` (0064) declares a PL/pgSQL local named `tz`, and its standings subquery selects `from challenge_participants cp join profiles p`. **0099 added `profiles.tz`.** From that migration onward an unqualified `tz` inside that scope named both a variable and a column, and PostgreSQL refuses to guess — so every tap on a competition, by every athlete, returned the error. ⚠ **The hub never hit it** (`challenge_hub()` has no such local), which is why the list worked and only the detail failed. **Fixed by renaming the locals to `v_tz`/`v_k`**, the convention every function written after 0099 already uses; nothing else in the function moves. `challenge_results_detail()` (0072) gets the same rename **pre-emptively** — it is not broken today (its `tz` references sit inside derived tables `profiles` is not in scope for) but it declares the same two bare names one join away from the identical failure, and leaving that standing is exactly how 0064 got here. `challenge_score`/`challenge_baseline`/`challenge_type_leader` are deliberately untouched: every reference there is in an expression with no FROM clause, so there is no relation to be ambiguous with.

**(2) The invite was never *not sent* — it stopped existing before it could be.** Create Challenge defaults to **"Starts Today"**, and today means **midnight this morning, already past**. The creator is then routed to `/competitions`, whose first act is `advance_challenges()`. **So the competition is ACTIVE within seconds of creation, before the invitee opens anything.** Both surfaces that offer a competition to somebody who has not joined tested `state = 'ENROLLMENT'`: `notification_events_for()` branch 6 (the `/inbox` row, the bell count, and via `push_enqueue_for` the push) and `challenge_hub()`'s `open` list (the only place the **Join** button lives). **Scoring is unaffected** — `challenge_score()` measures everyone over `start_at → end_at`, so a late joiner is scored across the same window from a standing start and nobody's number moves. **This widens SQUAD too, deliberately:** a member who did not opt in before their squad's competition began hit the identical dead end. **"Open to Join" now has to say so** — the row carries `state` and reads `underway · N days left` when it is already running, because the section header alone implies "hasn't started".
